# MNT-0021: 保守者環境のPrivate更新元

- Classification: MAINTENANCE
- Status: cancelled
- Related: MNT-0020、GOV-0005、REL-0004
- Requested: 2026-10-17
- Cancelled: 2026-10-17（本人判断）

## 取り下げの決定

開発はPrivate正本で行い、保守者本人の日常利用環境も `yamazaki/codex-starter-kit` の正式Releaseを参照する方針に変更した。一般利用者に近い条件で継続利用でき、Private専用の自動更新経路は不要になったため、本件を取り下げる。コードへの実装やPrivate更新元への設定変更は行っていない。以下は取り下げ前の要望・検討案として保持する。

## 要望と現在の差

利用者は `yamazaki/codex-starter-kit`、保守者本人は `yamazaki/codex-starter-kit-private` を更新元にしたい、という要望。現行`.5`は正式Releaseのリポジトリを公開用に固定し、Private保守treeは明示的な手動更新に限っている。フォルダ名やGit remoteで自動的に切り替える実装ではない。共通エンジンで取得元だけを変えられる、という以前の説明は、Privateからの自動更新まで実装済みという意味ではなかった点を訂正する。

## 次の設計案

- 公開利用者の既定は公開用の受入済み正式Releaseのまま維持する。
- 保守者だけがPrivate側の更新経路を明示的に選択できるようにする。認証を配布物や設定へ複製せず、非公開情報を公開候補へ混入させない。
- 推奨は、Privateでも受入済みの版・固定commitを対象にする方法。未受入の`main`やローカル作業treeを無条件に自動適用する方式にはしない。
- Private側で何を受入単位にするか、公開用との同一版・異なる内容をどう識別するか、取得物へ`internal/`等を含めない方法を設計する。
- 更新元変更のレビュー、権限不足時の停止、認証情報非表示、現在構成保持、排他、バックアップ、復元、Hookの信頼境界を検証する。

## 今回の扱い

要件の記録と現行制限の案内だけ。更新コード、配布物、正式`.5`のtag、本人の設定、Hook・信頼状態は変更しない。次の改訂での実装・受入・本人環境への適用は別作業とする。現行`.5`の公開準備を、この未実装機能への置換と混同しない。
