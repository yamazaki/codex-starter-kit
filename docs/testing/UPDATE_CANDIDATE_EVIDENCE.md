# 次版の更新機能に必要な検証

MNT-0020/REL-0006の開発用チェックリスト。VERSION/packageを `.5` 候補へ更新したが、未リリース・未受入である。[候補計画](update-candidate-plan.json)は変更一覧とhashを固定するpending記録であり、受入済みの証拠対応表ではない。

## 既存の証拠を保持する

正式 `.4` の対応表は、配布物と導入機構を含む76対象が旧試験対象と同一であることを確認する契約である。通常の `install.mjs` を変更すると、この契約では新しいコードを検証済みと扱えない。対応表のhashを更新して済ませず、新しい版の変更範囲と試験を別に記録する。既存の不合格・修正・受入記録と実際の試験版は変更しない。

## 正式受入とリリース後の確認を分ける

新しい[受入証拠](update-release-evidence.json)は、旧 `.4` 対応表を保持したまま75の未変更対象・変更installer・更新機構を分ける。旧対応表のhash、installer/runtime/回帰試験のhash、最新起動要約、3 OS結果を照合する。内容の逸脱・証拠の改変・試験のスキップ・本人受入の欠落を拒否する。現在はpending-owner-reviewで、候補を正式版へ昇格していない。

正式リリース前: 最新差分の自己レビュー、検証器の回帰/3 OS CI、最終機密検査、本人による未確認範囲を含めた受入とリリース承認。正式 `.5` の取得試験は、存在しないReleaseを先に取得できないためリリース後の確認項目にする。

リリース後: `yamazaki/codex-starter-kit`をPrivateのまま固定tag/commitで取得し、隔離環境で更新/構成保持/復元を確認する。その後、別承認で本人のローカル環境へ更新、必要なら更新Hookを登録し正式レビュー・信頼、新しいチャットと日常利用で確認する。Public化は本人のGoを待つ。Windows/Linuxの実Codex・稼働中チャットへの影響・部分更新の自動復旧は未検証/未提供の境界として残す。

共通ロックは、既存インストールに対する更新・削除・復元の競合を対象にする。インストール前で管理領域がない初回導入同士の同時実行、稼働中チャットが保持するSkill/agentの読み込み状態、異常終了からの自動復旧は、今回のロック試験の保証範囲ではない。

候補の `install.mjs` は変更済みであり、旧 `.4` の同一性対応表をそのまま適用できない。構造検査では変更をinstallerだけに限定して追加runtimeのhashも固定するが、通常の動作証拠の受入やモデル試験の開始許可とは分ける。旧版の原記録を新候補へimportせず、registered updaterの更新は `update.mjs` を使用する。
