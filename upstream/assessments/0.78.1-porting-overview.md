## この文書の目的

本家の全機能を、Codex版でどこへ移植・再構成・除外したかを一つの入口から確認できるようにする。`ADAPT`はファイルのコピーを意味せず、目的・workflow・安全境界を保持しながらCodexのSkills、custom agents、AGENTS、Hooks、installer、native機能へ変換したものを含む。

詳細な機械可読正本は`porting/fidelity-contract.json`と各mapであり、この文書は利用者・保守者向けの全体像である。

### maintenanceへ統合した3件

`audit-config`、`update-kit-dry-run`、`update-kit`は`codex-starter-kit-maintenance`へ統合した。本家の自動pull・setup処理は再現せず、installed manifest、dry-run plan、明示apply、snapshot、rollbackへ置き換えた。

### DROPした1件

`spec-kit-init`は外部CLIとSDD方法論をprojectへ追加するためcoreから除外した。必要なprojectで現在の公式Codex互換性とlicenseを確認し、独立optional Skillとして採用する。

## Rules

project固有AGENTSを優先し、利用者が追加したglobal AGENTSはinstallerが暗黙上書きしない。

## Permissions

`config/permissions.json`はClaude固有DSLのため、そのまま配布しない。deny 57件・allow 87件を次へ逐項mappingした。

- secret・credential path: AGENTSのprivate path境界
- destructive filesystem・Git command: safety-net＋明示approval
- privileged・network・remote shell・GUI command: external/privileged approval
- shell profile変更: user-owned config approval
- 一般的なread/write/build/test command: repository sandbox内で実行し、escalation時はapproval

本家のallowはCodexでのglobal pre-approvalを意味しない。Codex sandboxと現在のapproval policyが常に優先される。

## ConfigとPlugins

| Config | 判断 |
| --- | --- |
| `settings-base.json` | language、profiles、optional Hookをinstaller planへADAPT |
| `permissions.json` | `permissions-map.json`へADAPT |
| `plugins.json` | Claude marketplace lifecycleをDROP |

15 pluginsはいずれもretained coreのhard dependencyではない。setup/uninstall、plugin adoption、pending feature通知がconsumerだったが、Codex版ではそのlifecycleを配布しない。

LSP、security、document、review系はrepository-native tool、Codex Skill・agent、optional Codex pluginと一部重複するが、完全同等とは主張しない。詳細は[plugin依存関係監査](0.78.1-plugin-dependency-audit.md)を参照する。

## Distribution engine

本家の更新・merge・backup思想を、Codex向けに次の構造へ再実装した。

- `minimal / standard / full` profiles
- 日本語・英語
- `$CODEX_HOME`と`$HOME/.agents`の2 root
- dry-runとapplyの分離
- manifestによる所有管理
- stale fingerprint・symlink・modified fileのfail-closed停止
- snapshot、uninstall、rollback
- user-owned global AGENTSの明示PRESERVE
- optional safety-netとHook trust review

## Fidelity contract

`porting/fidelity-contract.json`は、13 Skills、29 Skill resources、9 agents、21 commands、8 rules、config 3 files、permissions 144 entries、18 features・48 filesを対象とする。

source SHA-256、disposition、target evidence、required section、adaptation boundaryを検証し、新しい本家assetが未分類のままacceptedになることを防ぐ。contractは人の意味判断を代替せず、証拠なしに完了扱いすることを防ぐ。
