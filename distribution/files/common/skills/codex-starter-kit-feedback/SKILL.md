# Codex Starter Kit feedback

1. Classify the request as bug, feature, upstream port, documentation, question, or security.
2. Gather only information needed for the report: kit version or commit, selected profile, operating system, expected behavior, actual behavior, and minimal reproduction.
3. Do not read or include credential values, environment variable values, auth files, Codex sessions, prompt history, unrelated logs, HOME paths, usernames, or private repository URLs. Prefer a short sanitized excerpt over a full log.
4. Route questions and open-ended ideas to Discussions; route actionable bugs and improvements to Issues; route concrete changes to Pull Requests.
5. For a vulnerability, leaked secret, or non-public information, do not create a public report. Follow `SECURITY.md` and use private vulnerability reporting. If no private channel is available, prepare a non-sensitive request for a safe contact method.
6. Produce the complete destination, title, and Markdown body as a preview. If repository details or a submission tool are unavailable, stop after producing the copyable draft.
7. Require explicit approval immediately before creating or updating any Issue, Discussion, Pull Request, or private security report. Do not treat approval to draft as approval to submit.

State any omitted or unverified environment detail instead of guessing it.
