# Strategic Compact Skill

Use logical boundaries when context has gone stale or work must continue in another task. Do not interrupt a coherent implementation merely because many tool calls have occurred.

## When Compacting Pays Off

- **After exploration, before execution** — Compact research context, keep the implementation plan
- **After completing a milestone** — Fresh start for the next phase
- **Before major context shifts** — Clear exploration context before a different task

## Best Practices

1. **Handoff after planning** - Preserve the accepted plan, evidence, and approval boundaries before implementation starts elsewhere.
2. **Handoff after debugging** - Keep the root cause, failed attempts, and exact verification state.
3. **Do not split mid-implementation** - Preserve context for related changes unless compaction or a task boundary is unavoidable.
4. **Trust the harness** - Codex manages automatic compaction; a durable repository handoff is for cross-task continuity and important state that must survive context loss.

Record the objective, accepted decisions, files or systems changed, verification performed, open failures, actions not authorized, worktree state, and next concrete step. Use the repository's existing work record or session-history location and never include secrets.
